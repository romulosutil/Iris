## 1. Objetivo e fronteiras

**Entrega:** calendário semanal com **duas visões** (por-terapeuta /
por-paciente) + **select-first** (comboboxes por nome, mata o UUID cru) +
criação de `agendamento_recorrente` (regra standing) e de `session` avulsa
(avaliação/devolutiva/reunião) + **detecção de conflito**.

**Não entrega (dívida explícita — Etapas D/E/F):**
- Materialização em lote/IANA de ocorrências, "esta e futuras", estender
  horizonte, idempotência de materialização → **Etapa D**.
- Ciclo de vida da sessão (estados realizada/falta/cancelada, substituto
  `atendidoPorId`, reposição `repostaDe`, modalidade) → **Etapa E**.
- Métricas alocado/vago, alerta de defasagem, teto de horas do paciente
  → **Etapa F**.
- **Fuso IANA:** a Etapa C usa **hora crua** como a B (B5). Não lê
  `clinic.timezone`, não cria "segunda verdade de fuso". A unificação é da
  Etapa D (materialização).

**Reusa sem editar:** `src/lib/agenda/{janela,grade,bloqueio}.ts`,
`src/db/schema.ts` (`session` enriquecida, `agendamento_recorrente`),
`src/components/ui/*`, `src/app/(app)/agenda/fuso.ts`,
`agenda/estado-badge.tsx`.

## 2. Decisões travadas nesta etapa

| # | Decisão |

| C3 | **Grade herda a orientação da Etapa B**: dias = linhas (dom→sáb), tempo = colunas horizontais. Fork de `grade-disponibilidade.tsx` → herda `role="grid"`, teclado, drag e testes a11y. |
| C4 | **Ambas as visões alocam.** Por-terapeuta: popover pede disciplina + paciente (terapeuta fixo). Por-paciente: popover pede disciplina + terapeuta (paciente fixo). |
| C5 | **Conflito checado nas 2 dimensões**: terapeuta ocupado E paciente ocupado. Pré-check app-level para regra + avulsa; EXCLUDE gist como backstop TOCTOU só para avulsa. |
| C6 | **Popover único com toggle Recorrente\|Avulsa.** Data/hora fixas pelo slot clicado. Avulsa = `recorrenteId=null` + `tipo` setado. |
| C7 | **`vigenciaInicio` = segunda-feira da semana VISÍVEL** (não `today`). Criar regra vendo semana futura não reivindica retroativamente a semana corrente. Resolve a ambiguidade do §6.4 do design mãe. |
| C8 | **Fora-da-janela = aviso suave; bloqueio = bloqueio duro.** Alocar fora da faixa de trabalho do terapeuta é permitido com aviso inline (terapeuta às vezes estende). Slot bloqueado (feriado/férias, escopo aplicável) **não aloca**. |

## 3. Leitura de dados

Para a **semana visível + entidade selecionada**, a grade projeta 4 camadas:

1. **Faixas de trabalho** (`janela_trabalho`) → fundo "dentro da janela"
   vs "fora-da-janela". Só na visão **por-terapeuta** (paciente não tem
   janela).
2. **Regras ativas** (`agendamento_recorrente`, `status='ativo'`, vigência
   cobrindo a semana) → **projetadas** no dia/hora da regra como blocos
   "ocupado (previsto)", dimensionados por `duracaoMin`. Sem linha
   `session`.
3. **Sessões avulsas** (`session` com `recorrenteId IS NULL`,
   `agendadaPara` na semana) → blocos "ocupado (concreto)".
4. **Bloqueios** (`bloqueio` do escopo aplicável: `clinica` sempre; +
   `terapeuta` na visão por-terapeuta / + `paciente` na visão
   por-paciente) → slots "bloqueado".

### 3.1 Query nova
`agenda/queries.ts` (ctx-accepting, **fora de `use server`**, padrão da
Etapa B para evitar RPC forjável):

```
carregarSemana(ctx: TenantContext, {
  eixo: 'terapeuta' | 'paciente',
  entidadeId: string,
  semanaInicioISO: string,      // segunda-feira da semana visível
}) → withTenant(ctx, tx => { janelas, regras, avulsas, bloqueios })
```

Recorte por intervalo de 7 dias reusando `idx_session_clinic_dia`. A
**projeção das regras** na semana (dia/hora → posição/tamanho na grade) é
lógica pura em `src/lib/agenda/projecao.ts` (testável sem banco).

### 3.2 Comboboxes (select-first)
- **Terapeuta:** `listarTerapeutas(ctx)` já existe (`equipe/[id]/queries.ts`).
- **Paciente:** **construir** `listarPacientes(ctx, termo)` — busca por
  nome, **só pacientes com consent LGPD ativo** (mantém o gate §4.6 do
  design mãe: alocação só após consent). Paciente sem consent simplesmente
  não aparece no combobox.

## 4. Componentes UI

- `agenda/semana/page.tsx` — rota nova **`/agenda/semana`**. Server
  component: resolve tenant, monta toggle de eixo + combobox de entidade +
  navegação de semana (‹ semana atual ›).
- `agenda/semana/calendario-semana.tsx` — **fork de
  `equipe/[id]/grade-disponibilidade.tsx`**: mesmo `role="grid"` 7×N,
  navegação por teclado (setas / Enter / Espaço), foco visível. A célula
  deixa de ser toggle binário — vira **slot** que pinta
  `livre / ocupado-previsto / ocupado-concreto / fora-da-janela /
  bloqueado` e dispara o popover no Enter/clique de slot **livre ou
  fora-da-janela** (bloqueado não abre).
- `agenda/semana/popover-alocar.tsx` — toggle Recorrente|Avulsa; select
  disciplina (Recorrente) / select tipo (Avulsa); combobox da entidade
  faltante; data+hora **read-only** do slot; `duracaoMin` pré-preenchido
  do `clinic.duracaoDisciplina[disciplina]`, editável. Usa
  `Form`/`Field`/`Alert` + tokens brutalist.
- `agenda/semana/combobox-entidade.tsx` — combobox a11y por nome
  (parametrizado paciente | terapeuta), reusável.

### 4.1 Estética (passada dedicada)
Estrutura funcional primeiro. Hierarquia visual, densidade da grade,
paleta dos estados de slot, distinção previsto/concreto (C9) e motion do
popover → passada com **/impeccable + frontend-design** depois que o fluxo
funciona. Grade de referência a cada `clinic.passoGradeMin`.

### 4.2 Empty states (produto)
- Terapeuta sem `janela_trabalho` configurada → grade vazia + CTA "Configurar
  disponibilidade" linkando `/equipe/[id]`.
- Nenhuma entidade selecionada → estado inicial pedindo seleção.
- Semana sem nada alocado → grade limpa (não é erro).

## 5. Escrita, conflito

### 5.1 Actions (`agenda/semana/actions.ts`, `"use server"`, thin)
`criarRegra` e `criarAvulsa` → resolvem tenant via `getTenantContext()`,
`requireRole(ctx, 'coordenador')` (defesa-em-profundidade; RLS é a
fronteira real), chamam a query ctx-accepting, tratam `RoleError`,
`revalidatePath('/agenda/semana')`.

### 5.2 Conflito — pré-check puro (`src/lib/agenda/conflito.ts`)
Dado o slot (dia/hora/`duracaoMin`) + entidade oposta escolhida, detecta
sobreposição contra **regras ativas E sessões avulsas**, nas **2
dimensões**:
- **terapeuta ocupado** naquele intervalo;
- **paciente ocupado** naquele intervalo.

Meia-aberto `[início, fim)` (mesmo modelo do EXCLUDE gist, `session_fim()`).
Bloqueia com `Alert` inline explicando qual dimensão colidiu.

### 5.3 Backstop de banco (avulsa)
`criarAvulsa` insere linha `session` real → protegida pelo **EXCLUDE gist**
(`session_no_overbook_terapeuta` / `_paciente`, `WHERE estado='agendada'`).
Erro do constraint (corrida TOCTOU entre pré-check e insert) é capturado e
mapeado para mensagem amigável, não 500 cru.

### 5.4 Avisos suaves (não bloqueiam — C8)
- Slot **fora-da-janela** do terapeuta → aviso inline, alocação permitida.
- Na visão **por-paciente**, ao escolher o terapeuta, valida o slot contra
  a janela + ocupação **dele** (a visão não carrega janelas) e mostra aviso
  se estiver fora/ocupado — cobre o ponto cego de alocar cego à
  disponibilidade do terapeuta.

## 6. Jornadas (com achados de produto/UX embutidos)

1. **Montar a semana de um terapeuta:** seleciona terapeuta → grade mostra
   janelas + ocupação → clica slot livre → popover Recorrente → disciplina
   (duração pré-preenchida) + paciente → confirma → cria regra com
   `vigenciaInicio` = segunda da semana visível (C7).
2. **Ver a semana de uma criança (cross-terapeuta):** seleciona paciente →
   grade mostra a semana inteira dela, de todos os terapeutas → responde a
   pergunta diária do coordenador (ponto cego que a v1 tinha).
3. **Alocar pela visão da criança:** clica slot livre → popover Recorrente
   → disciplina + terapeuta → aviso suave se o terapeuta estiver
   fora-da-janela/ocupado (5.4) → confirma → cria regra.
4. **Agendar um one-off:** clica slot → toggle Avulsa → tipo
   (avaliação/devolutiva/reunião_pais/outro) + entidade faltante → cria
   `session` avulsa (protegida pelo EXCLUDE).
5. **Colisão:** pré-check barra com `Alert` dizendo se colidiu no terapeuta
   ou no paciente; corrida concorrente em avulsa cai no EXCLUDE → mensagem
   amigável.

## 7. Testes

- **Unit (sem banco):** projeção de regras na semana (`projecao.ts`);
  detecção de conflito (`conflito.ts`) nas 2 dimensões, regra×regra e
  regra×avulsa, borda meia-aberta; recorte de camadas; cálculo de
  `vigenciaInicio` pela semana visível (C7).
- **Integração (Postgres):** RLS de `carregarSemana`/`criarRegra`/
  `criarAvulsa`; IDOR via FK composta `(patientId, clinicId)`; EXCLUDE gist
  barrando avulsa concorrente; `listarPacientes` respeitando o gate de
  consent.
- **a11y:** axe nas telas novas (`/agenda/semana`, popover) com
  **`color-contrast` religado** (padrão D3-revisada); operabilidade por
  teclado via `user-event` (navegação de slot, abrir popover, confirmar),
  não por axe.

## 8. Riscos residuais

- **Projeção sem materialização (C1):** a grade mostra "ocupado (previsto)"
  computado da regra, mas não há linha `session`. Se a Etapa D materializar
  com regra de fuso diferente da projeção crua da Etapa C, os blocos podem
  deslocar 1h numa virada de DST. Mitigado por C9 (rótulo "previsto") +
  a Etapa D ser dona única do fuso; a projeção da C é explicitamente
  "estimativa em hora crua".
- **`listarPacientes` e superfície de dado pessoal:** busca por nome é novo
  vetor de leitura de PII — restrito a coordenador (RLS) + só consentidos.
- **Fork da grade diverge da Etapa B:** dois componentes `role="grid"`
  parecidos podem divergir em manutenção. Aceito na v1; extrair base comum
  é candidato a refactor pós-Etapa C se a duplicação incomodar.

## 9. Posicionamento

Etapa C do design mãe. Depende de A (dados/constraints) e B
(disponibilidade/perfil de terapeuta) — ambas concluídas. Habilita D
(materialização), que consome as regras criadas aqui.
